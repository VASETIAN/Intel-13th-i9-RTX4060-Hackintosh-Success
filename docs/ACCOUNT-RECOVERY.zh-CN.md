# 首次设置卡住后的账户替代流程

本页记录已经在本项目使用的处理路线，不是通用一键建账户工具。原始 Setup Assistant 地区页问题没有证实被根治；最后通过经同意建立本地管理员，进入登录与桌面。

## 实际故障

已安装系统可以进入国家地区页；Continue 事件进入了进程，但页面不推进。原生线程快照定位到 CountryManager 保存语言区域后等待辅助服务回调。Wi-Fi 扫描超时是另一条线索，未证明为唯一原因。

8 GiB 内存限制对照未改善并撤回；结束 Setup Assistant 后系统退出临时设置会话并关机，后续重开命令没有运行。单核与 Swift 协作队列的调度解释仍属未完成验证的假说。

## 真正执行过的路径

1. 保留普通 EFI 和账户数据库备份，记录已安装系统 build。
2. 临时增加单用户维护参数，保留已有 CPU、ACPI、显卡、网络和机型配置。
3. 在维护环境确认 Darwin、root、正确 build、预期启动参数；拒绝仍有图形设置或登录会话的状态。
4. 确认目标 Data 卷、账户数据库及挂载关系确实属于这套已安装系统。
5. 输入本地账户名，以原生 Directory Services 处理账户、管理员成员与主目录。密码由本人在隐藏提示中输入，不进入聊天、日志或命令参数记录。
6. 检查原生密码认证、管理员关系、主目录所有者与完整性、Secure Token。全部通过后才写首次设置完成标记 `/var/db/.AppleSetupDone`。
7. 恢复普通 EFI，确认不再有临时 `-s`，再正常进入图形登录。实际登录成功才算完成，而不以脚本语法检查或副本运行成功代替。

没有采用 `pycreateuserpkg`，没有使用 `.skipbuddy`，也没有把 `LIBDISPATCH_COOPERATIVE_POOL_STRICT=1` 作为本机修复。讨论过的外部建议不能写成实际实施内容。

## 两个脚本故障的处理

### 启动参数空白误判

旧程序把 `kern.bootargs` 整串逐字比较。OpenCore 的内部 slide 参数处理与实际日志支持尾部空白触发误判的解释，但当时没有直接保存该次 sysctl 返回值的完整原始字节。

修订只规范前导、尾部和重复空白，再进行有序、严格的参数比较；不排序、不忽略未知参数。缺少 `-s`、改动 `cpus=1`、多出未知参数或仍有内部 slide 参数都必须停止。独立 Sequoia 副本做过 22 个接受与拒绝检查。

仓库中的 [bootargs_guard.py](../tools/bootargs_guard.py) 是只读字符串示例，用于展示这个规则。它不会检测或修改当前系统、执行维护引导或创建账户。

### 密码认证失败后保留部分账户

原机曾返回 `Authentication for node /Local/Default failed` 和 `eDSAuthFailed`。程序 STOP 并保留部分账户，没有自动删除或重启。无法单凭照片判断是输入不一致还是认证环境问题。

随后只读检查发现普通账户、管理员成员和主目录已存在。因此续接程序不再创建、删除账户或重设密码，只对既有账户进行最多两次原生隐藏密码认证；通过后复核权限、主目录与 Secure Token，再写完成标记。最终原生验证报告成功，普通 EFI 已恢复，机主随后成功登录桌面。

## 为什么不公开现用账户脚本

现用程序绑定特定 Data UUID、系统 build、维护参数、已有账户身份以及当时的恢复任务条件；旧加载方式还绑定具体扇区位置和压缩长度。更换安装后这些值可能完全不同。仅替换字符串不足以把它变成通用可运行工具。

因此本仓库不附会写入账户、密码、标记或磁盘的实际执行程序，也不提供历史 `dd` 扇区提取命令。未来需要这条替代路线时，应按上面条件为当前安装重新核验；已有账户时优先续验，不能盲目重跑创建流程。正常首次设置可以完成的机器不需要此步骤。

标记只意味着设置流程被视为完成，不会替你创建有效账户或修复 Apple ID。不要用无条件创建标记的单条命令代替完整账户与认证检查。
